Simple Hack {{ .Chart.AppVersion }} is starting at https://{{ .Values.host }}/

Watch it come up (the first start builds the database, under a minute):

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "hack.name" . }}
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "hack.name" . }}

Before anyone can open it:

  1. DNS: {{ .Values.host }} and *.{{ .Values.host }} to the load balancer
     in front of the ingress (that one wildcard resolves team sites too).
  2. TLS at the load balancer for {{ .Values.host }}, *.{{ .Values.host }}
     and each event's *.<event>.{{ .Values.host }} (team sites), and
     X-Forwarded-Proto: https on what it forwards.
{{- if and (not .Values.ingress.events) (not .Values.ingress.catchAll) }}
     Team sites are not routed yet: list the event's slug under
     ingress.events once it is created, and helm upgrade.
{{- end }}
{{- if include "hack.oidcOn" . }}
  3. The identity provider's web client allows this redirect URI:
       https://{{ .Values.host }}/v1/auth/oauth/oidc/callback
{{- else if .Values.signIn.password.enabled }}
  3. Sign in with a username and password. Admin Users can create accounts
     and reset temporary passwords.
{{- else }}
  3. Sign-in is by emailed code through Resend; company sign-in (signIn.oidc)
     is the way in for an internal installation.
{{- end }}

The first organiser signs in at https://{{ .Values.host }}/ and creates the
event; no admin step is needed. The platform admin key (for /v1/admin/*):

  kubectl -n {{ .Release.Namespace }} get secret {{ include "hack.secretName" . }} -o jsonpath='{.data.ADMIN_API_KEY}' | base64 -d

docs/kubernetes.md has the upgrade, backup and troubleshooting steps.
