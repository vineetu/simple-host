Status: this is a new ChatGPT plugin, package simple-host. The old draft, package app-6ab570c7e41c81918c88f0026f2e1895, cannot gain an MCP server through a package upload; the portal says so directly ("create a new plugin"). The old draft is left alone; it does not block this one. Everything else carries over unchanged: the connector, the three skills, the reviewer account, and the test cases below.

Download Simple Host plugin 1.0.0 ZIP, built 2026-10-29, for the new plugin

plugin.json, the MCP connection (https://simple-host.app/mcp), three skills (website-deploy, website-deploy-builder, connect-domain), and the icons. The package name is simple-host, version 1.0.0.

Create a new plugin

  1. Open platform.openai.com/plugins and choose Create plugin, then With MCP. Package name simple-host (must match the ZIP's plugin.json).
  2. Upload the ZIP above as the plugin package. If its Skills tab asks for skills only, upload the skills ZIP there instead.
  3. Connect the MCP server, https://simple-host.app/mcp. When it asks you to sign in, choose "Reviewer sign-in" and use the account openai-review@simple-host.app (password: on the server, sudo cat /root/simple-host-reviewer-password, never on this page), then Allow. Verify the domain if the portal shows a new challenge token.
  4. Choose Scan Tools. Expect 55 tools, each with an output schema, and no UI templates.
  5. Fill in the listing fields below (copy buttons alongside each).
  6. In the Testing tab, either paste the cases below or upload chatgpt-app-submission.json in the "Use Codex" box. It holds the app info, all 55 tools with their three justifications, and the test cases.
  7. Paste the release notes, confirm the attestations, and choose Submit for Review. After approval, choose Publish.

The old draft, app-6ab570c7e41c81918c88f0026f2e1895, needs nothing further. It stays as is; abandoning it does not affect this new plugin.

Description (long)
Simple Host hosts websites you or your AI have made. Your AI puts the files online through the connector, at an address you can share, and Simple Host keeps them there. Publish a page you have made, update an existing site, or ask to see its saved entries.

Each site can save key-value data (KV), SQLite tables, and files. Access presets control who can read, add, edit, and delete data. New resources are private by default. Use an inbox for submissions only the owner reads, records for each signed-in visitor's entries with owner access, or public data for content everyone may read. Visitors sign in with Google or an emailed code; no password or sign-up form.

Update site files, preview a saved version, or restore an earlier version. The four latest site versions are kept by default, and deleted sites can be restored for 7 days. Current storage stays until you delete it or its site; it does not have automatic 30-day change history.

Connect your own domain with HTTPS or choose a short name.simple-host.app address. Manage who can open a site, read visitor counts and top pages, and download a copy of your site.

Connect your Simple Host account through the app's sign-in flow. You can revoke the connection from the Simple Host dashboard. Simple Host is open source, made and run by Vineet Sriram.

Testing tab

Five positive and three negative cases. The demo account sites are at https://<site>.<handle>.simple-host.app/.

Positive 1. Put a one-page site online as a new site.

User prompt

Put a one-page website online for my bakery, Rise and Shine, as a new site named rise-and-shine. It should list our opening hours: Monday to Friday 7 to 3, Saturday 8 to 1.

Tools triggered

create_site

Expected output

Says the site name and address and that anyone with the link can open it, waits for a yes, then calls create_site once and returns the live https://rise-and-shine.<handle>.simple-host.app/ address. The page shows the bakery name and hours. No photo, notification, or identity calls, and no emails in the result.

Positive 2. Update the seeded feedback survey and undo the requested change.

User prompt

On feedback-survey, change the heading to "Tell us how we did". Then, in the same chat: Undo that change.

Tools triggered

get_site, read_site_file, update_site, list_versions, rollback_site

Expected output

The survey shows the requested heading. After confirmation of the rollback, the previous version restores the original heading. No account or visitor emails are returned.

Positive 3. Read only the requested order details from the seeded pickle shop.

User prompt

Show the orders saved by pickle-shop, including items, totals, and status.

Tools triggered

storage_sql_query

Expected output

Queries only items, total_cents, and status in the orders resource and returns the four seeded orders. No customer names, contacts, emails, or unrelated records are returned, and nothing is changed.

Positive 4. Count RSVPs without identifying visitors.

User prompt

How many RSVPs do I have on garden-party-rsvp?

Tools triggered

storage_sql_query

Expected output

Returns COUNT(*) from the rsvps table in the rsvps resource, matching the current fixture count. Returns no emails, names, or visitor references. Does not call who_am_i or storage_visitor_emails.

Positive 5. Visitor numbers without per-visitor detail.

User prompt

How many people visited feedback-survey this week, and which pages did they read?

Tools triggered

site_analytics

Expected output

Returns visit totals, daily counts, and top pages for feedback-survey. The result has no IP addresses, locations of individuals, emails, or visitor identifiers. Nothing is changed.

Negative 1. Brainstorming does not authorize hosting or account access.

User prompt

Help me brainstorm names for my new hair salon.

Why Simple Host should not be used

Answers in chat with name ideas. Does not call any Simple Host tool or publish anything.

Negative 2. An uploaded server application is outside the hosting service.

User prompt

Deploy my Node.js API with a Postgres database to production.

Why Simple Host should not be used

Explains that Simple Host serves static files and its built-in storage; it does not run your own server code. No deployment occurs. Offers to discuss a static frontend if useful.

Negative 3. Summarizing an unrelated external website is outside the connector.

User prompt

Summarize what is on https://example.com for me.

Why Simple Host should not be used

Explains that Simple Host does not retrieve arbitrary external pages. Makes no Simple Host call and does not direct another connector to run.

What changed since September

  • The connector works on the free plans of ChatGPT, Claude, and Grok.
  • In ChatGPT, people add Simple Host from the Plugins page: Add, then Add custom MCP server, name it Simple Host, paste https://simple-host.app/mcp, save, sign in, and choose Allow.
  • Saved data uses KV, SQLite, and file storage with access presets. Each preset sets who may read, add, edit, and delete: public, inbox, wall, comments, records, personal, board, and private. With comments, anyone posts to a guestbook, comment thread, or reviews without signing in, after a Cloudflare Turnstile spam check, and the owner can approve each post first. The get_page_recipe tool returns working page code for bookings, waitlists, client portals, menus, orders, guestbooks, and other everyday jobs.
  • The older saved-data routes (state, collections, and declared data) closed to new sites on 2026-10-12. Sites created before then keep working.
  • Sites can have a passcode or open only to the people the owner names, and every person can pick a site as their home page.
  • simple-host.app names its owner, Vineet Sriram, in the footer and on the Privacy and Support pages.
