# Simple Hack UX atlas

The living map of every Simple Hack screen: the design of each one, who it is for, which
features it holds, and a picture of every state at 390 and 1280 px, grouped by role.
Published at https://simple-hack-ux-atlas.vineetu.simple-host.app/.

**The atlas changes before the app does.** A new feature, or a change to where something lives,
starts here: add it to `features.json`, give it a home on a screen in `spec.json`, add a line to
`changelog.json`. Then build the screen in `web/hack` (see `web/hack/README.md`) with a
catalogue state for each case, accept its baselines, rebuild the atlas and publish.

| File | What it is |
|---|---|
| `spec.json` | The design: app shell, sidebar per role, every screen (moment, purpose, main action, sections, states, decisions, features) |
| `features.json` | Every capability, with role, stages, API route and MCP tool. Each id must appear on a screen |
| `catalogue.json` | Generated by `build.py` from the app's catalogue: every screen and state, grouped by role, with its picture name. Do not edit |
| `changelog.json` | What changed in the atlas, newest first |
| `index.html` | The atlas viewer |

The pictures are the catalogue's baselines (`web/hack/tests/baseline/<state>-390.png` and
`-1280.png`, made by `make hack-web-accept`); the build writes them into `dist/pictures` as WebP.

```
python3 docs/ux-atlas/build.py --check    # read-only offline checks
python3 docs/ux-atlas/build.py            # regenerate catalogue.json, build dist/ (needs web/node_modules and Pillow)
python3 docs/ux-atlas/build.py --publish  # and publish the site (uses ~/.website-deploy/config.json)
```

`build.py` fails on features with no screen, screens naming unknown features, a feature whose
`feature` field does not name an anchor in FEATURES.md (see `docs/feature-ids.txt`), a spec
screen with no catalogue state, a state missing a picture, or a baseline picture
`catalogue.json` does not list. Keep these at zero.
