# Simple Hack UX atlas

The living map of every Simple Hack screen: the design for each one, who it is for, which
features it holds, a clickable prototype, and how it looks in production today.
Published at https://simple-hack-ux-atlas.vineetu.simple-host.app/.

**The atlas changes before the app does.** A new feature, or a change to where something lives,
starts here: add it to `features.json`, give it a home on a screen in `spec.json`, update that
screen's prototype file, add a line to `changelog.json`, publish. Then build the real thing
against the prototype.

| File | What it is |
|---|---|
| `spec.json` | The design: app shell, sidebar per role, every screen (moment, purpose, main action, sections, states, decisions, features, the today-screens it replaces) and sample events for the prototype |
| `features.json` | Every capability, with role, stages, API route and MCP tool. Each id must appear on a screen |
| `prototype/kit.css`, `shell.js` | The kit. Screens use only these. `shell.js` draws the switcher, sidebar, status header and phone tabs |
| `prototype/<screen-id>.html` | One screen. `<screen-id>~<state>.html` is the same screen in another state |
| `prototype/nav.js`, `files.json` | Generated by `build.py` from `spec.json`. Do not edit |
| `changelog.json` | What changed in the atlas, newest first |
| `index.html` | The atlas viewer |

Today's production screenshots are not in the repo (19 MB). They live in
`/home/ubuntu/simple-hack-ux-atlas-today/` (`atlas.json` + JPEGs), captured by
`scripts/e2e-hack/ux-atlas.mjs` on the `test/hack-forms-e2e` branch. Re-capture after a
redesigned screen ships.

```
python3 docs/ux-atlas/build.py            # checks + builds dist/
python3 docs/ux-atlas/build.py --publish  # and publishes the site
```

`build.py` reports features with no screen, screens naming unknown features, and screens with
no prototype file. Keep all three at zero.
