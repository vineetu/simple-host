D3-S1a declaration boundary (read beside mcp-identifiers.txt); D3-S1b additions at the end

Schema/declaration helpers: declare.go exposes thin wrappers for the typed
inventory's schema builders, annotations, argument parsers, description/meta
attachment and policy options. Policy and analytics fields remain private.
There is no exported registry, registry view, policy index or server inventory.

Tool adapters: Call/Output/UpstreamResult aliases retain the existing mechanics.
Do, Caller, WithCaller, Request, UICapable, MaxBodyBytes, CanSelectTarget, SelectTarget,
MemberResult and OrganiserResult cover the private call/server facts used by
Hack adapters. UpstreamResult's OK/Status/Header/Body cover REST replies.
WithPolicy replaces policy like the private helper; WithRun and CallTool
replace direct run-field writes/reads, with CallTool
preserving the base declaration's policy for app-only twins.

Screens: AppScreen/Request/Response, Result/Failure, protocol error constants,
AppMIME, AppFiles, AppFlag and FlatListApp expose the shared screen primitives.
The UI-declaration parser and listing loop/filter remain private platform code.
ShowAllowed accepts only Caller and the UI capability boolean.

New dependencies found after extracting product fragments: NotificationTools,
RequiresNotificationID, PageRecipeTool, RecipeTopics and ReadRecipe. Wording
constants used by the product have read-only exported aliases. Storage rules
use StorageRulesEnabled and StorageRulesInstructions. Span already existed.
EventStorageTools takes the product owner sentence and photo-wording function;
the current no-argument adapter remains in hack_storage_tools.go.

Shared helper found in a product file: upstreamMessage is used by Host's site
adapters too. It stays byte-for-byte platform code in upstream_message.go.

Transitional composition: NewServer, Inventory and the existing in-package
newRegistry shim live beside hackContribution in families_hack.go. They fill
an omitted Config.Contribution, without init-time registration. An explicit
&Contribution{} adds nothing. D3-S1b moves selection to the composition root.
The generic constructor, registry and dispatch use only the contribution.
HackTools still uses the private registry in this slice; D3-S1b replaces that
compatibility assembly with its own contributed families, without exporting it.
Family constants become product-owned family labels at that move.

Screen methods and call-time gates remain in Hack files until D3-S1c. The Apps
factory builds their transitional receiver from AppContext once per server.
No request data or serving Server is passed into the factory.

D3-S1b (declarations moved to products/hack/mcp): the product names its four
families by label ("hack-events", "hack-entries", "storage", "sites"); no
family constant, registry or inventory was exported. hackmcp.Tools() is the
flattened contribution. One helper was added: NewCall(server, request, caller),
which the moved tests use with CallTool where they used to build a call and
read the run field. Inventory now takes the product's Contribution. A nil
Config.Contribution adds nothing; the composition root passes Hack's through
extension.Parts.Tools and ConnectorHandler.SetTools.
The remnant families_hack.go appends the app-only family (built from the
contributed base tools, only for a contribution with the hack-events family)
and supplies Apps until D3-S1c. It also holds the screens' copies of
eventSlug, hackRestError and hackAbilitiesSchema, which leave with the screens.
host/mcp's in-package tests get the product from the external test file
hack_wire_test.go (transitional test edge mcp -> products/hack/mcp, D3-S1c).

D3-S1c (screens moved to products/hack/mcp): families_hack.go is gone. The
product's Contribution.Apps builds its screens once per server from AppContext
and supplies AppFamily; the registry appends that family after the product's
own (buildRegistry), and Inventory composes it the same way. Added to the
contract: AppContribution.SitesPage (the script and product name the
platform's own screens carry on a product connection; the product's
hack-sites.js moved with it), Contribution.MutationNames with RetiredMutation
(the answer for a retired tool name; today the two judging-lock names).
Config.SelectHackTeam and Config.MutationResultHook became SelectTarget and
MutationResult; Server.HackListedTools became ProductListedTools. Two helpers
were added for the product's tests: Call.WithUICapable and
Server.AnalyticsCopy. The product embeds its own screen files and its event
recipe (recipes/hack-event.md, both wordings); the shared bridge.js stays in
the platform (AppFiles). The family constants for Hack left registry.go.
host/mcp's tests use a fixture product (product_fixture_test.go); the test
edge mcp -> products/hack/mcp is removed from [transitional].
