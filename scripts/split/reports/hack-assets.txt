Decision recorded: what Replace holds
=====================================

products/hack/asset_files.go lists about 110 names, more than the brief's
description of Replace ("only platform names that a product replaces"). It
holds two kinds:
  1. platform names the product replaces (favicon.svg, auth.md, llms.txt,
     docs-site, setup/setup.js, .well-known/ard.json, ...);
  2. the product's own names that the platform's file server and page
     pipeline answered before the move (hack/app.js, hack-ink.css, the
     mp3s, ...), each mapped to itself, plus the directory names "hack",
     "hack/screens", "setup", ".well-known" and "docs-site" so a directory
     read lists the product's entries.
The one entry that is not a file name is "docs-site": it names the product's
docs tree and only docsTree reads it. The static lookup (selectedAssets.source)
skips it, so GET /docs-site on Hack answers 404 directly, as before the move
(TestProductDocsRootIsNotAStaticName, TestHackDocsRootIsNotServedAsAFile).
Kind 2 keeps every Hack address answering with the same bytes and headers
from the same file server (the golden run shows no Hack difference). The
lookup is still exact with no fallback: a file added to the product's embed
is unreachable until it is listed. The cost is that "a name only in Files is
reachable only through Routes" is weaker than the brief intends for kind 2;
moving those names behind one product file route is a follow-up, not done
here because it would change which handler answers them. Reading the
directory "setup" on Hack lists the product's folder, not the platform's;
nothing reads it today.

Host after the move
===================

A platform install has no Replace, so every moved file answers 404 there.
Before the move Host's file server answered them with 200 (all but the few
handlerOnlyFS hid, for example /hack-llms.txt). No platform page links to
any of them. scripts/golden/run.mjs requests a representative set on both
products and scripts/golden/approved/D3-S2a.json pins the Host 200 -> 404 for
/hack-ink.css, /og-hack.png, /favicon-hack.svg, /hack/app.js, /hack/kit.css,
/hack-watch-judge.mp3, /hack-directory.html, /hack-voting.html,
/hack-connect-steps.json and /hack-get-started-preview.png.

D3-S2b: what changed in the sections above
==========================================

The sections above are kept as D3-S2a wrote them; where they disagree with
this one, this one is current.

Replace and the product's own names (NOTES ruling 2 of 2026-11-15 12:40).
products/hack/asset_files.go now has two tables. assetReplacements (12
entries) holds only platform names. The product's own names (99) are in
extension.Assets.Own, split into servedOwnFiles (86: 84 files and the folders
"hack" and "hack/screens") and pageOnlyFiles (13 templates and pages that one
of Hack's routes renders). The self-mappings are gone from Replace.
  - The page pipeline still reads an own name (selectedAssets.source looks in
    Replace, then Own, then the platform's embed), because the platform
    renders Hack's pages.
  - The platform's file server never answers an own name: its view of the
    tree hides them (handlerOnlyFS.hidden). The hack-* names that
    handlerOnlyPages and handlerOnlyFS.Open listed are deleted from the
    platform.
  - Over HTTP an own name is answered by handler.AssetServices.ProductFiles(),
    a new method: the same chain as the platform's fallback (CSP, chrome on
    HTML, file server, this install's 404 page) over a view that does not
    hide them. Hack mounts it in Assets.Routes through RegisterOwnFiles, at
    "GET /<name>" for each served name and "GET /<name>/{$}" for the two
    folders. A page-only name gets no address, so it answers the 404 it
    answered before.
  - Measured, not argued: 330 requests (every old Replace key with and
    without a trailing slash, HEAD, Range, conditional and query forms, the
    film files, the downloads) against the binary before and after, on Host,
    on simple-hack.app and on a self-hosted Hack. Hack: identical in both
    modes. Host: only the 12 film files below differ.
AssetServices therefore has six methods, one more than the brief lists.

D3-S3: reference and public-text branches
========================================
The earlier sections are historical. OpenAPISpec is gone: the product replaces
openapi.json/yaml with its generated public contract, and the platform keeps
only generic audience filtering. The unserved composed internal contract is
used for route coverage. Feature JSON and HTML also use explicit replacements;
the product's Rewrite resolves its JSON markers, while the shared server keeps
only the hosted/self bracket pass. The product's setup-helper.html carries its
setup words. Its PersonalPresentationHTML callback makes the enterprise page's
event link local. Shared docs choose their replacement root, and the llms.txt
instance note follows the absence of a product text hook.
