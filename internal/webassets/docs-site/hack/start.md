# Run an event

1. [Connect your AI app](/get-started), or sign in and press **Create event**.
2. Ask: “Create a hackathon called Better Commutes.” Add the event dates, then open the event's **Home**.
3. In **Event page**, fill in the event details. In **Settings → Entries**, choose what teams hand in. In **Settings → Judging**, set the rubric and press **Mark as final** when it is ready. Tracks live on **Event page → Tracks**.
4. Follow the checklist on **Home**. Unfinished optional rows have **Not needed** and **Use this item**. Completed rows show the recorded facts. Use **Home** to open sign-up. Copy the **Join link** from **Home** and send it to participants; copy the **Judge link** there for judges. To learn what any setting or option means, or what happens if you change it, press **Ask** at the bottom right of any organiser screen: it answers in a few lines and links to where to change it. It never changes anything itself.
5. Follow the next-step button on **Home** to start building, close entries, start judging, and publish results. Confirm each stage change. **Your events** stays in the pane; open another event there to switch, including its mark when the pane is collapsed.

Use `hack_get_checklist` with the event slug and `role: "organiser"` for current tasks and the next action. Confirm changes before writing.

**Mark as final** acknowledges the rubric version you loaded. If someone changes it before you confirm, refresh and read the updated criteria. On Results, resolve every tied group before the checklist marks tied places done; the editor uses the current preview even after an earlier publication.

Choose **Organisers who also judge** in Settings → Judging and save with the assignment mode. Organisers start unticked; organisers with existing scores start ticked. This same judge list supplies queues, assignments and counts. Starting Judging shows the mode, judges per team, judge names and coverage with links to fix them; you can start anyway. Informational checklist rows have no button.
