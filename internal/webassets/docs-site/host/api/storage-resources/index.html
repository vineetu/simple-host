Storage resources

Owner-declared KV, SQLite and durable file resources.

POST /v1/sites/{sitename}/storage/files/{name}/download-link

Mint a ten-minute scoped full-byte download link (owner only)

Auth: an API key (X-API-Key header, or a REST-audience connector token as Authorization: Bearer).

Parameters:

Name In Type Required Description
sitename path string yes
name path string yes
Idempotency-Key header string Opaque key for a create request. For 24 hours, the same authenticated account, POST path and query, key and exact request body replay the original handler status and body, including errors, without executing it again. A different body under that key returns 409 idempotency_key_reused. Concurrent identical requests wait for the first response. Stored only in this server’s memory; a restart clears it. Authentication and rate limiting still apply to replays. A replay does not extend a minted link’s expiry; use a new key to request a new link. Storage row creates support owner credentials and signed-in visitors; anonymous writes ignore this header. Storage replay also checks current resource permissions and is scoped to the resolved site.

Request body:

Name Type Required Description
path string yes

Responses:

Status Description
200 {url,expires_at}; bearer URL remains private and is rechecked when used
409 Idempotency-Key reused with a different body (idempotency_key_reused).

PUT /v1/sites/{sitename}/storage/files/{name}/objects/{path}

The server decides add (a new path, checked against add, published without replacing) or edit (an existing path, checked against edit; own edits only by the author, who stays the author). A caller who may add but not edit gets 409 file_exists. The owner’s tools can always replace. File growth beyond the separate website allowance returns site_full with photo-shrinking tips. Empty files count toward SITE_STORAGE_FILES_MAX_OBJECTS (1000 per bucket by default); bucket_full is 507. New upload paths are normalized to NFC; reads and deletes accept exact legacy paths. Paths allow at most 16 segments.

Request body: application/octet-stream

Responses:

Status Description
200 {path,bytes,content_type}

The server decides add (the key does not exist; checked against add, created with ON CONFLICT DO NOTHING) or edit (it exists; checked against edit, own edits carry the author check in the UPDATE and keep the original author). Parameters:

Responses:

Status Description

PUT /v1/sites/{sitename}/storage/resources/{name}

Kind is immutable. Simple Host: set preset (public, inbox, wall, comments, records, personal, board, private; default private) with optional single-action overrides read, add, edit, delete, or preset custom with all four. Each action takes nobody, owner, own, signed-in or anyone; add also takes checked (anyone who passes the Cloudflare Turnstile spam check: the comments preset, read anyone / add checked / edit owner / delete owner). The server refuses (400 invalid_access, with rule) edit or delete anyone (anonymous_change), add own (add_own), own anywhere with add anyone or checked (own_needs_sign_in), checked on read, edit or delete (checked_add_only), and edit or delete wider than read (change_wider_than_read). checked is refused on files resources, and with 400 spam_check_unavailable on a server without TURNSTILE_SITE_KEY and a secret. approve_first (SQLite, needs a checked add) holds posts added through the check: the server adds approved_at TEXT to those tables (rows already there count as approved), visitors see and reach only rows with approved_at set, and the owner approves with UPDATE … SET approved_at = datetime(‘now’). Omit approve_first to keep it. SQLite: the preset is the database default; tables sets a preset per table (omit to keep the current table presets, {} to clear). Tables whose preset uses own or lets visitors add get the server-owned visitor_id TEXT column and index. The older read, write and write_mode are still accepted and translated (write anyone with full is refused as anonymous_change; omitting write_mode on update keeps the mode); do not mix them with preset fields. Switching a legacy SQLite database pages wrote with SQL to a preset that uses own needs empty tables (visitor_id_required). Owner here means the owner’s tools and the owner signed in on the site’s own address through visitor sign-in; nobody means the owner’s tools only.

Auth: an API key (X-API-Key header, or a REST-audience connector token as Authorization: Bearer).

Parameters:

Name In Type Required Description
sitename path string yes
name path string yes

Request body:

Name Type Required Description
add string, one of nobody, owner, signed-in, checked, anyone
approve_first boolean
delete string, one of nobody, owner, own, signed-in
edit string, one of nobody, owner, own, signed-in
kind string, one of kv, sqlite, files yes
preset string, one of public, inbox, wall, comments, records, personal, board, private, custom
read string, one of nobody, owner, own, signed-in, anyone
site_passcode string, one of inherit, False
tables object
write string, one of anyone, signed-in, owner older field
write_mode string, one of full, add older field

Responses:

400 invalid_access (with rule), invalid_resource, visitor_id_required

GET /v1/sites/{sitename}/storage/sqlite/{name}/tables/{table}/rows

Checked against the table’s read value (its own preset, or the database’s). Equality filters where.{column}=value (at most three, real columns only) are bound values. Visitors see their own visitor_id and null for other people’s, plus mine per row; visitor_id cannot be filtered or ordered by visitors. Own reads use WHERE visitor_id = ? with the stable site-session identity. Table and order columns are checked against real schema; values are bound. Default order is an unshadowed rowid alias ascending; ordinary rowid tables only. Cursor includes order value and rowid, bound on the next query with matching order/desc. Owner sees all. No visitor SQL accepted. HEAD is a read. Visitor tables are limited to 100 columns and the complete response to SITE_STORAGE_SQL_RESULT_MAX_BYTES; visitor queries time out after one second. Reads do not lock writes or deploys.

sitename path string yes
name path string yes
table path string yes
order query string
desc query integer, one of 0, 1
limit query integer
after query string
where query object where.{column}=value, equality, at most three

Responses:

Status Description

POST /v1/sites/{sitename}/storage/sqlite/{name}/tables/{table}/rows

Checked against the table’s add value. One JSON object of real column names and scalar values. The server builds INSERT OR ABORT with bound values; visitor-supplied primary keys and rowids are refused. SQLite assigns the IDs and RETURNING supplies the result. Visitor visitor_id, created_at and updated_at are ignored; visitor_id is filled from the site session and created_at with UTC time when the columns exist. Declared SQLite foreign keys must point at a row the visitor may read under the parent table’s read value (for own, a row they added), checked inside the insert transaction. Missing and unreadable parents both return 404 invalid_reference; the insert is rolled back. Optional references must be all NULL; partial composite NULLs are refused. A trigger or foreign-key action that writes another table refuses the insert (403). No visitor SQL accepted. Where add is checked (the comments preset), a caller other than the owner sends the one-time Turnstile token in X-SH-Turnstile (auth.js does it on its own); without one 403 spam_check_required, a failed, reused, expired or mismatched one 403 spam_check_failed, Cloudflare unreachable 403 spam_check_unavailable. The token must have been solved in the frame at GET /v1/turnstile/frame for this host and resource. Such a post is at most SPAM_CHECKED_POST_MAX_BYTES (413 post_too_large) with at most SPAM_CHECKED_POST_MAX_LINKS links (400 too_many_links), and RATE_LIMIT_SPAM_CHECKED_IP and RATE_LIMIT_SPAM_CHECKED_SITE apply (429). The same holds for adding a KV key. The query param for (owner, or the owner signed in on the site’s own address, only; SIM-358, 2026-11-06, review fixes 2026-11-06) adds this row for one other signed-in visitor instead of the caller, by their visitor_id or the email they signed in with, only on a table whose read is own (403 for_requires_own on any other table, checked on the table’s own matrix). It is refused (404 visitor_unknown) if they have never signed in on this site, or (400 visitor_email_ambiguous) if more than one signed-in person currently matches that email; there is no pre-sign-in email binding. The server ignores any visitor_id or written_by the caller sends and sets them itself, visitor_id to that visitor and written_by (added lazily, under the write lock, the first time a table is used this way; 409 written_by_blocked if a trigger or view appears to depend on the table) to owner, otherwise the empty string, which is also written_by’s value whenever for is absent, including a plain owner add. A row added this way does not fire record.added to the owner’s own subscriptions.

Storage row creates support owner credentials and signed-in visitors; anonymous writes ignore this header. Storage replay also checks current resource permissions and is scoped to the resolved site.
sitename path string yes
name path string yes
table path string yes

GET /v1/sites/{sitename}/storage/usage

Host KV/SQLite share 10000000 bytes per website; files have a separate 10000000-byte allowance. The single-upload default remains 1000000 bytes. Deployed website assets and legacy saved data have separate limits. SQLite main database bytes are counted after checkpoint; transient WAL is excluded. KV key bytes count too. File buckets have at most SITE_STORAGE_FILES_MAX_OBJECTS (default 1000) committed objects, including empty files.

Auth: an API key (X-API-Key header, or a REST-audience connector token as Authorization: Bearer).

Parameters:

Name In Type Required Description
sitename path string yes

Responses:

Status Description
200 {used_bytes,limit_bytes,remaining_bytes,files_used_bytes,files_limit_bytes,files_remaining_bytes,breakdown:{kv_bytes,sqlite_bytes,files_bytes}}
403 forbidden

GET /v1/sites/{sitename}/storage/visitors

Owner only (key or connector). Turns visitor_id values from this site’s saved data (the visitor_id column of read-own SQLite tables; visitor_id on KV keys and stored files, which only the owner’s reads show) into the email each person signs in with, and, with email instead of (or combined with) id (SIM-358, 2026-11-06), the other direction: the visitor_id they signed in as, for a for request or ResolveOwnerFor directly. Only people who signed in on this site as visitors resolve (recorded by the server when a visitor session starts, never read from the site’s own tables; found false otherwise; no pre-sign-in email binding). 1 to 100 ids and/or emails total, comma-separated or repeated.

Auth: an API key (X-API-Key header, or a REST-audience connector token as Authorization: Bearer).

Parameters:

Name In Type Required Description
sitename path string yes
id query string visitor_id values, comma-separated (or repeat id=)
email query string Email addresses, comma-separated (or repeat email=). Combine with id, or give this alone.

Responses:

Status Description
200 visitors: [{visitor_id?, email?, found}], one entry per id then per email, in that order
400 invalid_visitor_id
403 forbidden (not the owner)
