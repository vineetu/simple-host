Simple Hack (https://simple-hack.app): Hackathons, now for everyone. Anyone can build with AI; the best idea wins, not the best coder. Participants describe their idea and AI builds their team site, with no coding needed. Organisers run events for college students, product managers, leaders and people who are not programmers.

Use the signed-in Simple Hack connector at https://simple-hack.app/mcp. Its trusted browser sign-in gives the person's current organiser, participant, judge and selected-team permissions. Do not ask for sign-in codes, API keys, team keys, passwords or passcodes in chat. Start at https://simple-hack.app/get-started for the five current skills and their references. In Meta Muse (Settings, Connectors, Add custom connector) the MCP URL is https://simple-hack.app/mcp and the Client ID is meta-muse (the document at https://simple-hack.app/.well-known/muse-client.json also works as a Client ID, but meta-muse is short enough that a phone keyboard cannot mangle it). Lovable, Bolt and Cursor have setup steps at /get-started#lovable, /get-started#bolt and /get-started#cursor. Any other AI app (including Codex, Replit, v0 and Windsurf) uses /get-started#other: add this instance’s /mcp address as a custom MCP connector with OAuth, sign in in the Simple Hack window, then choose Allow. In Gemini (personal Google account in the US: Settings, Connected Apps, Add a custom app) and Mistral Vibe, formerly Le Chat (Connectors, Add Connector, Custom MCP Connector), paste https://simple-hack.app/mcp, sign in, and choose Allow.

Team websites and organiser custom event websites publish static files. Their active storage choices are owner-declared key-value resources, per-site SQLite resources and raw-file resources. Each resource has a storage preset that says who may read, add, edit and delete (read / add / edit / delete): public (anyone / owner / owner / owner), inbox (owner / anyone / owner / owner), wall (anyone / signed-in / owner / own), records (own / signed-in / owner / owner), personal (own / signed-in / own / own), board (signed-in / signed-in / signed-in / owner) or private (all owner, the default); own is the signed-in visitor who added the entry, and SQLite can set a preset per table. The server refuses anonymous edit or delete, add own, own with anonymous add, and edit or delete wider than read. Owner on a team site is the team: the storage_* tools with the team selected, and a team member signed in on the team site with their Simple Hack email (owner rights for saved data only) until Judging starts or the team's submission deadline passes, whichever is earlier. Owner on a custom event website is the organisers: the hack_event_storage_* tools, and an organiser signed in on the event website until the event ends. hack_get_page_recipe returns the setup and a working page for each preset. An owner may let a resource inherit the site's existing passcode gate or turn that inheritance off. The default 1,000,000-byte allowance is pooled across these new resources for each website. Resize phone photos before storing them as files.

Use storage_* tools for a selected team site and hack_event_storage_* tools for an organiser's custom event website. A public page uses SH.storage.kv(), SH.storage.sqlite(db).table(t) (list, get, add, edit, delete; pages never send SQL on a resource with a preset) or SH.storage.files() from https://simple-hack.app/auth.js; SH.mount(), SH.email and SH.requireSignIn() handle visitor sessions when a preset needs signed-in visitors. Team membership, event stage, deadline and organiser role checks remain server enforced. Joining, applications, team entries, judging and results are native event features on the trusted Simple Hack apex, separate from website storage.

Simple Hack organiser deletion: DELETE /v1/hack/events/{slug} with {"confirm":"<slug>"} works at any stage. Empty, unended events retain no-body deletion; otherwise 409 delete_only_empty explains confirmation. Settings requires typing the address name. Pages, results, team sites, entries, scores, votes, custom website, storage and access are removed permanently with no undo. Names stay reserved after anyone joins. The destructive hack_delete_event tool and run-hackathon always ask before deleting.

Simple Hack for companies (https://simple-hack.app/companies): the self-hosted package (app, Postgres and Caddy on one small server with Docker) runs a company's own hackathon. Company sign-in: OIDC_ISSUER, OIDC_CLIENT_ID and OIDC_CLIENT_SECRET add "Sign in with your company account" (OIDC_LABEL names it) for organisers, teams, judges, team-site visitors and the connector's sign-in; ALLOWED_EMAIL_DOMAINS limits it to the company's domains; EMAIL_SIGNIN=off turns emailed codes off. Register https://<your-domain>/v1/auth/oauth/oidc/callback at the identity provider. Inside the company network: install.sh --tls internal (Caddy's own CA), --tls acme --acme-ca URL (the company's ACME server), or --tls certs --cert-dir DIR (the company's certificates), plus --ca-cert FILE for an internal root. GET /v1/auth/oauth/providers lists oidc and oidc_label when it is on. Guide: https://github.com/vineetu/simple-host/blob/main/docs/platforms/simple-hack-standalone.md

The API reference includes public event and team routes, account sign-in, team-site deployment and versions, visitor sign-in, current site storage, skills and health.

Simple Hack: new events are unlisted until the organiser opts in. Judging freezes all entries including extensions. GET results returns 200 with published:false before publication. Simple Hack stage and Overview (2026-10-31): hack_get_event returns next_step, the one forward
move the website's Overview button offers for the current stage. Moving the stage to results
also locks judging in the same step, when it was not locked already. Participants and judges
see the same stage pill and stage track as organisers, plus a separate scoring pill for judges.

A schedule that acts (2026-11-02): hack_get_content returns fixed_schedule beside schedule, the
event's real times as read-only rows marked fixed: true (event start and end, the entry deadline
or the caller's own team extension, the voting window, results published), each with set_in
naming where it changes. Never send them back. A schedule row's optional prompt (open, building,
closed, judging, results or publish_results) makes next_step.cue ask for that move once the row
starts, e.g. "Kickoff is now. Open sign-up?", and the entry deadline always asks to close
entries. The cue only asks: the stage never moves by itself, so confirm with the organiser.

Teams (redesigned 2026-10-31): a team's creator is its first admin. Admins approve or decline
join requests, lock or unlock the team, rename it, edit its looking-for note, remove members,
make or remove other admins, and roll a new link, https://<hack host>/team/<code>, read with
hack_preview_team_link before joining. The last admin can't be unmade until someone else is
one, and the longest-standing remaining member takes over when an admin leaves. Locking clears
the team's pending requests and invites, and a locked team refuses every way in except
organiser placement. hack_create_team drops open, and hack_set_team_finding is gone, replaced
by the admin-only hack_update_my_team, hack_lock_my_team, hack_set_teammate_admin and
hack_new_my_team_link (organiser equivalents: hack_lock_team, hack_set_team_admin,
hack_new_team_link). hack_join_team's code takes a bare code or the whole link.

Team finding (SIM-225): private to approved participants and organisers, on by default, and
separate from locking. hack_list_open_teams reads every unlocked team (full flag included),
solo listings and pending offers. There is no "who can join" choice on a team any more, so a
former code-only team simply appears in this list too. Accepting or declining a request now
needs a team admin, invites stay any teammate's to send and the invitee's own to accept or
decline. hack_withdraw_team_request is unchanged. hack_remove_teammate is admin only and no
longer needs team finding on. Joining by any method clears other pending offers and the solo
listing, and leaving restores nothing. Organisers use hack_fill_teams with body.apply:false,
show the plan and confirm, then body.apply:true to place approved solo people into teams with
room, topped up to body.size (people per team, default 4), and new Team 1, Team 2 groups of
that size, avoiding name clashes and skipping locked teams. The apply plan uses current
membership. hack_update_event still accepts team_finding: off hides the lists and pending
offers and refuses new requests and invites, while codes, links, locking, admins and Fill
teams keep working either way.

Judging opens scoring. Finish judging (Results) locks it; moving back reopens it. On the website, stage changes and publishing (including tie order) happen only from organiser Home. The former judging lock/unlock routes return 410 judging_lock_removed.
