=== About Simple Host (public summary) ===

Simple Host (https://simple-host.app) hosts static websites and gives every site a small backend for saved data, in the same upload. People mostly never touch it directly: they tell their AI app or coding agent "put this online", and the agent registers, builds and deploys through the Simple Host skill or the Simple Host connector (ChatGPT, Claude, Grok and coding agents such as Claude Code, Codex and Cursor).

What a site gets:
- Its own address, https://<site>.<handle>.simple-host.app/, which is its own browser origin. A person's page lists their public sites at https://<handle>.simple-host.app/. A site can also use a free <name>.simple-host.app name or the person's own domain, with HTTPS.
- Saved data: one shared JSON document per site (state) with atomic operations, and lists (collections) for things like RSVPs, votes and guestbooks. Saved data has a 30-day undo. Pages save with the hosted helper script auth.js.
- Each piece of saved data has a kind. Data a page saves without declaring one is Shared: public, anyone can read it, and visitors can add to it (a guestbook, a counter). The owner's agent can declare it instead as Page info (one document only the owner changes and everyone reads: a menu, hours, prices) or as Submissions (things visitors send, like RSVPs, orders and sign-ups: private to the owner unless made public, and each visitor sees, changes and withdraws only their own). Two more kinds: Personal (one private record per signed-in visitor that follows them to any device, like a habit tracker or saved progress; Simple Host's owner tools never show it, only how many people have one; the site's own pages can read it for that visitor, so use it only on sites you trust) and Shared board (a list anyone reads and signed-in visitors add to, change and delete item by item, like a shared shopping list; only the owner clears it, and changes appear by polling, not instantly). So a name is one of four declared kinds (Page info, Submissions, Personal, Shared board), or Shared when nobody declared it. The owner chooses who may save (anyone who signs in, or only listed emails and domains) and can block a person.
- Visitor sign-in on the site's own address, with Google or an emailed code, so saves are per person. Submissions need the site's own address, where visitors sign in.
- Versions and rollback, previews before going live, renames that keep old links working, taking a site offline, analytics of people versus bots (with each site's top pages and the domains visitors came from), and a download of a site or of all of a person's data.

Accounts: sign in with an emailed six-digit code or Google; no password. Agents use an API key or the connector's sign-in. A key can be deploy-only (publish, roll back and list sites, nothing else: for a CI secret, which can create a site and publish it in one call) and can have a fixed expiry. A key unused for 180 days stops working. Connected AI apps show the browser each connection was approved on.

Pages are always public to anyone with the address; there is no password lock. Only private Submissions (and private lists) and Personal records (which the site's own pages read for their own visitor) are private; Shared data and Shared boards are public. There is no server-side code for site authors: pages run in the visitor's browser.

Getting started: to just use Simple Host, sign up free at https://simple-host.app/ and add it to your AI app (https://simple-host.app/install.html). To run your own copy on one server with Docker (a small box: self-hosting, a team or a hackathon), use the setup helper at https://simple-host.app/setup?product=small-box. It asks a few questions (or every setting, in Advanced mode) and writes the one-line install command and settings. For a company's own Kubernetes cluster (Simple Host Enterprise), the same helper is at https://simple-host.app/setup?product=enterprise. When someone asks how to install it, try it, get started, self-host it or run it in their company, answer in a sentence or two and link the right one of these.
The setup helper builds the files in the browser and never asks for a password or key. Just before showing the files, where this server has its model backend, it can check the chosen settings for likely mistakes (a warning per setting, each with Apply or Ignore; it can be skipped). That check sends only the product and the names and values of the settings changed from their defaults, nothing about the person. Every setting is explained in the advanced settings docs of each repository.

It is one Go program, one Postgres database and one folder of files.
