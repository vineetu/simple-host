Installing Simple Host Enterprise: what goes wrong, how to confirm it, the fix. The package's INSTALL.md has a runbook and a troubleshooting table; these are its common cases.

Where to look: kubectl -n simple-host get pods; kubectl -n simple-host logs deploy/simple-host -c migrate (the database step) and -c simple-host (the server); kubectl -n simple-host describe pod <pod> for scheduling, image and probe errors. Health: curl -fsS https://<address>/readyz answers {"status":"ok"}.

The server refuses to start (its log names the reason; a value out of range or unsafe is refused at startup with a message naming the setting):
- "missing required configuration: ...": required values are unset; the message lists all of them at once. Fill them in config.env or secrets.env, apply again and restart the deployment.
- A setting out of range or in the wrong format: the message names it; the SETTINGS list has its range and default. SESSION_IDLE must not be longer than SESSION_TTL (at most 8h). IDLE_CLEANUP_DAYS is 0 or at least 30. NETWORK_ACCESS_APPROVALS is 1 or 2. API_KEY_MAX_DAYS is 1 to 365.
- Refuses the database TLS: DB_SSLMODE must be verify-full with the provider's CA saved as db-ca.crt; a CNAME of your own for the database host fails verify-full, use the provider's endpoint name. On Azure the private DNS zone must resolve that same name.
- Refuses the bucket endpoint: it must be https://.
- Refuses SESSION_SIGNING_KEY: it is <id>:<base64 of 32 bytes>, one or two comma-separated; regenerate it with echo "k1:$(openssl rand -base64 32)".
- "BACKUP_STORAGE_ACCESS_KEY_ID and BACKUP_STORAGE_SECRET_ACCESS_KEY must be set together": set both or neither.
- OIDC_ADMIN_CLAIM refused: set it together with OIDC_ADMIN_VALUE, or neither.
- With Google Workspace, ALLOWED_EMAIL_DOMAINS empty is refused.
- Entra ID's multi-tenant issuers (/common, /organizations, /consumers) are refused: use the tenant's own issuer, https://login.microsoftonline.com/<tenant id>/v2.0.
- "can alter or delete audit_events": the server is connected as the owning role; keep DB_APP_USER and do not point DB_DSN at the owning role.
- DB_PASSWORD equal to DB_APP_PASSWORD is refused: they must differ.
- "schema version N is newer than this binary knows": the image is older than the database; roll forward to a newer image.

Crash loops and readiness:
- The pod crash-loops with "discover OIDC provider": the issuer is unreachable from the pod, or OIDC_ISSUER is wrong. Confirm from inside the cluster: kubectl -n simple-host run oidc-check --rm -i --restart=Never --image=curlimages/curl -- curl -fsS <issuer>/.well-known/openid-configuration. Fix egress (firewall, proxy, private DNS) or the issuer.
- /readyz returns 503: the database is not reachable or the schema is not current; read the migrate and server logs.
- The migrate step fails with a permission error: the owning role cannot create tables or roles; use the cloud's admin user or grant CREATEROLE.
- The migrate step fails creating the extension pgcrypto: the migrations create pgcrypto, and some managed Postgres services need it allow-listed first (Azure flexible server: set the azure.extensions parameter to PGCRYPTO).
- The migrate step cannot connect: the network path from pods to the database (security group, authorised networks, private endpoint).
- CronJob in ImagePullBackOff: the pull secret is on the Deployment instead of the ServiceAccount.
- The pod is refused on clusters older than Kubernetes 1.30 (its preStop uses the native sleep action).

Sign-in:
- A redirect-URI error at the callback: the registered redirect URI must be exactly https://<address>/auth/callback.
- Fails at token exchange: wrong client secret, or the provider does not accept client_secret_post for this app.
- "the identity provider did not send an email address": add the email claim, or set OIDC_EMAIL_CLAIM.
- "your email address is not verified": the ID token needs email_verified true; Entra ID never sends it, so add the optional claim xms_edov to the app registration.
- "this account's email domain is not allowed": ALLOWED_EMAIL_DOMAINS does not include the person's domain.
- A signed-in admin does not see /admin: their address is not in ADMIN_EMAILS, or the admin claim does not match; it takes effect at the next sign-in.
- 429 or "gave no redirect" after many sign-ins: sign-in is rate limited per address; wait two to three minutes.

Addresses, certificates and uploads:
- A person's or site's address gives a DNS or TLS error: one wildcard DNS record must cover *.<address> at every depth, and each owner's *.<owner>.<address> certificate needs DNS-01 (a wildcard cannot use HTTP-01) or an internal CA issuer.
- Sites stay at <owner>.<address>/<site>/: the owner's certificate is not ready. Check OWNER_CERT_ISSUER names a ClusterIssuer that exists, and kubectl describe certificate for that owner.
- A certificate never becomes ready: the DNS-01 solver's credential or zone; kubectl describe the certificate, order and challenge.
- Upload fails with 413: the ingress body-size limit (the package sets 128m for ingress-nginx); raise it with MAX_ARCHIVE_BYTES.
- Pods run out of memory on uploads: memory needed is about MAX_ARCHIVE_BYTES times UPLOAD_CONCURRENCY plus headroom; lower UPLOAD_CONCURRENCY or raise the pod's memory limit.

Bucket:
- Writes refused with "Server side encryption specified but KMS is not configured": self-hosted MinIO without a KMS backend.
- UpCloud Object Storage refuses writes with 400 XAmzContentSHA256Mismatch on older images: set AWS_REQUEST_CHECKSUM_CALCULATION=when_required and AWS_RESPONSE_CHECKSUM_VALIDATION=when_required.
- Bucket versioning must be on: it is what recovery comes from.
- Workload identity works only where the AWS SDK's credential chain reads it (AWS). On Google Cloud Storage and Azure use static keys (an HMAC key on Google Cloud).

Clouds:
- kubectl times out or says EOF on a new UpCloud cluster: its API admits no addresses until you add yours to the allow-list.
- UpCloud's load balancer must pass TCP through with PROXY protocol, or every host gets the load balancer's certificate and every client looks like one address.
- Azure free-trial subscriptions may refuse to create a Postgres flexible server ("The location is restricted from performing this operation"); a quota request or pay-as-you-go fixes it.
- Google's ManagedCertificate does not issue wildcards.
