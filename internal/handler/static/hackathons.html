Simple Host for hackathons

A hackathon for people who have never deployed anything.

Participants bring an AI agent they already use. Each of them gets a place where what they make goes live, and every entry is a link.

Today that place is simple-host.app, which is free to use. Running an event on a server of your own is not ready yet; the gaps are listed at the bottom of this page.

01.

Who this is for

A company where few people write code for a living but most have Claude Code, Codex, Cursor or Copilot. A college class. A team offsite. Any group whose members have not deployed a website before.

A participant needs a browser and an agent that can run a skill. Nothing gets installed on the machine beyond the skill itself.

02.

What a participant does

  1. Signs in at simple-host.app with an emailed code or Google. That gives them an API key and a profile page.
  2. Installs the Website Deploy skill from the get-started page. For Claude Code that is one command; other agents have their own steps on the same page.
  3. Tells the agent what they want. "A page where people can sign up for a slot." "A quiz about our product." "A dashboard for this spreadsheet."
  4. Gets a link. If the page needs to save anything, it has one JSON document of up to 1 MB and append-only collections, with no backend work.
  5. Changes it. Every deploy is versioned, so an earlier version of the files is one rollback away. Saved data is not versioned.

The deploy itself is one upload. Each account can hold 100 sites, and each site can be public on the profile page or hidden from it.

03.

What the organiser does

Before

Send the sign-in link and the get-started page. There are no accounts to create. Ask each team to send you their final link, since one account can hold several sites.

During

Nothing. Participants deploy as often as they like.

Judging

Every entry is a link. Judges open the links. For a first pass by a model, give an agent the list of links and ask it to fetch and summarise each one.

Traffic

Each participant's own dashboard shows views and visitors per site, split into people, bots and monitoring, with countries.

Saved data is open on simple-host.app. Anyone who can load a page can change that site's JSON document and add to its collections. The files change only with the owner's API key. If an entry's saved data matters for judging, have the team take a copy before judging starts.

04.

Not built

Do not plan an event around any of these.

Your own serverThe code is MIT and the README runs it on a laptop. The fresh-server runbook predates the current site layout, and the skill points at simple-host.app rather than your instance. Both are being updated. My workplace instance, on a 1 CPU, 1 GB box, costs $5 a month, and that is the target for events too.
Docker Compose and KubernetesDocker is documented for local development only. There is no Compose file or Kubernetes manifest.
Organiser viewNo screen that lists an event's entries, and no scores or tags. The organiser keeps the list of links.
Per-person savesSign-in before saving exists only on a site with its own domain. On simple-host.app saved data is open to anyone who loads the page.
AI inside the pagesNo per-site model allowance. A page that calls a model needs a key from somewhere, and anything in the page is public.
Pre-issued keysNo organiser tool for handing out accounts in advance. Everyone signs up with their email or Google.
05.

Start

Sign in at simple-host.app, install the skill, and ask your agent for a page. That is the whole participant flow, so try it yourself before the event.
