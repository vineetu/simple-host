Simple Hack (https://simple-hack.app): Hackathons, now for everyone. Anyone can build with AI; the best idea wins, not the best coder. Participants describe their idea and AI builds their team site, with no coding needed. Organisers run events for college students, product managers, leaders and people who are not programmers.

Use the signed-in Simple Hack connector at https://simple-hack.app/mcp. Its trusted browser sign-in gives the person's current organiser, participant, judge and selected-team permissions. Do not ask for sign-in codes, API keys, team keys, passwords or passcodes in chat. Start at https://simple-hack.app/get-started for the five current skills and their references. In Meta Muse (Settings, Connectors, Add custom connector) the MCP URL is https://simple-hack.app/mcp and the Client ID is meta-muse (the document at https://simple-hack.app/.well-known/muse-client.json also works as a Client ID, but meta-muse is short enough that a phone keyboard cannot mangle it). In Gemini (personal Google account in the US: Settings, Connected Apps, Add a custom app) and Mistral Vibe, formerly Le Chat (Connectors, Add Connector, Custom MCP Connector), paste https://simple-hack.app/mcp, sign in, and choose Allow.

Team websites and organiser custom event websites publish static files. Their active storage choices are owner-declared key-value resources, per-site SQLite resources and raw-file resources. Each resource has a storage preset that says who may read, add, edit and delete (read / add / edit / delete): public (anyone / owner / owner / owner), inbox (owner / anyone / owner / owner), wall (anyone / signed-in / owner / own), records (own / signed-in / owner / owner), personal (own / signed-in / own / own), board (signed-in / signed-in / signed-in / owner) or private (all owner, the default); own is the signed-in visitor who added the entry, and SQLite can set a preset per table. The server refuses anonymous edit or delete, add own, own with anonymous add, and edit or delete wider than read. Owner on a team site is the team: the storage_* tools with the team selected, and a team member signed in on the team site with their Simple Hack email (owner rights for saved data only) until Judging starts or the team's submission deadline passes, whichever is earlier. Owner on a custom event website is the organisers: the hack_event_storage_* tools, and an organiser signed in on the event website until the event ends. hack_get_page_recipe returns the setup and a working page for each preset. An owner may let a resource inherit the site's existing passcode gate or turn that inheritance off. The default 1,000,000-byte allowance is pooled across these new resources for each website. Resize phone photos before storing them as files.

Use storage_* tools for a selected team site and hack_event_storage_* tools for an organiser's custom event website. A public page uses SH.storage.kv(), SH.storage.sqlite(db).table(t) (list, get, add, edit, delete; pages never send SQL on a resource with a preset) or SH.storage.files() from https://simple-hack.app/auth.js; SH.mount(), SH.email and SH.requireSignIn() handle visitor sessions when a preset needs signed-in visitors. Team membership, event stage, deadline and organiser role checks remain server enforced. Joining, applications, team entries, judging and results are native event features on the trusted Simple Hack apex, separate from website storage.

Reference: https://simple-hack.app/docs.html; schemas: /openapi.json and /openapi.yaml. /auth.md describes this instance's sign-in, connector OAuth, and selected team. Public discovery: /.well-known/mcp/server-card.json, /.well-known/agent-card.json, /.well-known/ard.json, and /.well-known/api-catalog. The landing supports Accept: text/markdown, /index.md, and /llms.md; root Link headers advertise discovery.

Presentation: the hosted home is the approved 12-scene story, with return-visit actions. All app screens share the local paper-and-ink theme. PATCH /v1/hack/events/{slug} accepts accent_color: empty for a stable slug colour, or red, teal, indigo, orange, yellow, grass, blush. Event, list and public reads expose color for the matching accent.

Simple Hack organiser deletion: DELETE /v1/hack/events/{slug} with {"confirm":"<slug>"} works at any stage. Empty, unended events retain no-body deletion; otherwise 409 delete_only_empty explains confirmation. Settings requires typing the address name. Pages, results, team sites, entries, scores, votes, custom website, storage and access are removed permanently with no undo. Names stay reserved after anyone joins. The destructive hack_delete_event tool and run-hackathon always ask before deleting.

Simple Hack for companies (https://simple-hack.app/companies): the self-hosted package (app, Postgres and Caddy on one small server with Docker) runs a company's own hackathon. Company sign-in: OIDC_ISSUER, OIDC_CLIENT_ID and OIDC_CLIENT_SECRET add "Sign in with your company account" (OIDC_LABEL names it) for organisers, teams, judges, team-site visitors and the connector's sign-in; ALLOWED_EMAIL_DOMAINS limits it to the company's domains; EMAIL_SIGNIN=off turns emailed codes off. Register https://<your-domain>/v1/auth/oauth/oidc/callback at the identity provider. Inside the company network: install.sh --tls internal (Caddy's own CA), --tls acme --acme-ca URL (the company's ACME server), or --tls certs --cert-dir DIR (the company's certificates), plus --ca-cert FILE for an internal root. GET /v1/auth/oauth/providers lists oidc and oidc_label when it is on. Guide: https://github.com/vineetu/simple-host/blob/main/docs/platforms/simple-hack-standalone.md

The API reference includes public event and team routes, account sign-in, team-site deployment and versions, visitor sign-in, current site storage, skills and health.

Watch https://simple-hack.app/watch for three short role films and copyable connector prompts. HACK_DEMO_EVENT_SLUG defaults to demo. /demo/join and /demo/judge redirect to its current invitation links or show a 404 page. These routes are hosted-only; no demo event is created by a lookup.

Self-hosted package MCP_APP_* flags persist across upgrades, default off; Hack product gates still apply. Use tool text when no screen is offered.

Visitor-save notifications: MCP Events and signed webhooks on team and organiser websites, managed with list_notifications and remove_notification (REST: /v1/sites/{sitename}/notifications or /v1/hack/events/{slug}/website/notifications). Team subscriptions need approved membership and creation before the submission deadline; organiser delivery ends with the event. PASSCODE_ENC_KEY is required; public HTTPS callbacks only.

Simple Hack: new events are unlisted until the organiser opts in. Judging freezes all entries including extensions. GET results returns 200 with published:false before publication. Voting settings return votes_to_remove counts by eligibility; narrowing eligibility removes invalid votes and returns votes_removed. Ask before removing earlier votes. Empty notification lists return 200 for an authorised website even before it is published.


Team finding (SIM-225): private to approved participants and organisers, on by default.
Use hack_list_open_teams to read open team rosters, solo listings and pending offers;
hack_ask_to_join, hack_invite_to_team, hack_accept_team_request,
hack_decline_team_request and hack_withdraw_team_request handle requests/invites.
hack_set_team_finding sets open and looking_for (one line, max 120 characters);
hack_set_looking sets looking and intro (one line, max 120 characters).
hack_create_team accepts optional open (default true) and looking_for.
hack_remove_teammate removes another teammate after confirmation. Use hack_leave_team for yourself.
Joining by any method clears other pending offers and the solo listing; leaving restores nothing.
Organisers use hack_fill_teams with body.apply:false, show the plan and confirm,
then body.apply:true to place approved solo people into open teams with room and
new Team 1, Team 2 groups up to the event maximum, avoiding name clashes.
The apply plan uses current membership. hack_update_event accepts team_finding.
Off hides stored pending offers and refuses finding actions; team codes still work.
REST paths under /v1/hack/events/{slug}/: GET teams/open; PUT team/finding
{open,looking_for}; PUT me/looking {looking,intro}; POST teams/{team}/requests;
POST team/invites {user_id}; POST requests/{id}/{action} (accept or decline);
DELETE requests/{id}; DELETE team/members/{user_id}; POST teams/fill {apply}.
Lists never appear on the public event page. Full teams cannot accept or invite.
