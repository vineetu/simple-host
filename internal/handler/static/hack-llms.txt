Simple Hack (https://simple-hack.app): Hackathons, now for everyone. Anyone can build with AI; the best idea wins, not the best coder. Participants describe their idea and AI builds their team site, with no coding needed. Organisers run events for college students, product managers, leaders and people who are not programmers.

Use the signed-in Simple Hack connector at https://simple-hack.app/mcp. Its trusted browser sign-in gives the person's current organiser, participant, judge and selected-team permissions. Do not ask for sign-in codes, API keys, team keys, passwords or passcodes in chat. Start at https://simple-hack.app/get-started for the five current skills and their references.

Team websites and organiser custom event websites publish static files. Their active storage choices are owner-declared key-value resources, per-site SQLite resources and raw-file resources. Each resource has a separate read and write policy: owner, signed-in or anyone. Signed-in access grants the whole resource; it is not per-person record privacy. An owner may let a resource inherit the site's existing passcode gate or turn that inheritance off. The default 1,000,000-byte allowance is pooled across these new resources for each website. Resize phone photos before storing them as files.

Use storage_* tools for a selected team site and hack_event_storage_* tools for an organiser's custom event website. A public page uses SH.storage.kv(), SH.storage.sqlite() or SH.storage.files() from https://simple-hack.app/auth.js; SH.mount(), SH.email and SH.requireSignIn() handle visitor sessions when a resource policy requires them. Team membership, event stage, deadline and organiser role checks remain server enforced. Joining, applications, team entries, judging and results are native event features on the trusted Simple Hack apex, separate from website storage.

REST reference: https://simple-hack.app/docs.html. API schemas: https://simple-hack.app/openapi.json or /openapi.yaml. Current reviewed skills: https://simple-hack.app/get-started.

Presentation: the hosted home is the approved 12-scene story, with return-visit actions. All app screens share the local paper-and-ink theme. PATCH /v1/hack/events/{slug} accepts accent_color: empty for a stable slug colour, or red, teal, indigo, orange, yellow, grass, blush. Event, list and public reads expose color for the matching accent.

Simple Hack organiser deletion: DELETE /v1/hack/events/{slug} with {"confirm":"<slug>"} works at any stage. Empty, unended events retain no-body deletion; otherwise 409 delete_only_empty explains confirmation. Settings requires typing the address name. Pages, results, team sites, entries, scores, votes, custom website, storage and access are removed permanently with no undo. Names stay reserved after anyone joins. The destructive hack_delete_event tool and run-hackathon always ask before deleting.

The API reference includes public event and team routes, account sign-in, team-site deployment and versions, visitor sign-in, current site storage, skills and health.
