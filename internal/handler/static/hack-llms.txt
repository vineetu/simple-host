Simple Hack (https://simple-hack.app): Hackathons, now for everyone. Anyone can build with AI; the best idea wins, not the best coder. Participants describe their idea and AI builds their team site, with no coding needed. Organisers run events for college students, product managers, leaders and people who are not programmers.

Use the signed-in Simple Hack connector at https://simple-hack.app/mcp. Its trusted browser sign-in gives the person's current organiser, participant, judge and selected-team permissions. Do not ask for sign-in codes, API keys, team keys, passwords or passcodes in chat. Start at https://simple-hack.app/get-started for the five current skills and their references.

Team websites and organiser custom event websites publish static files. Their active storage choices are owner-declared key-value resources, per-site SQLite resources and raw-file resources. Each resource has a storage preset that says who may read, add, edit and delete (read / add / edit / delete): public (anyone / owner / owner / owner), inbox (owner / anyone / owner / owner), wall (anyone / signed-in / owner / own), records (own / signed-in / owner / owner), personal (own / signed-in / own / own), board (signed-in / signed-in / signed-in / owner) or private (all owner, the default); own is the signed-in visitor who added the entry, and SQLite can set a preset per table. The server refuses anonymous edit or delete, add own, own with anonymous add, and edit or delete wider than read. Owner on a team site is the team: the storage_* tools with the team selected, and a team member signed in on the team site with their Simple Hack email (owner rights for saved data only) until the team's submission deadline. Owner on a custom event website is the organisers: the hack_event_storage_* tools, and an organiser signed in on the event website until the event ends. hack_get_page_recipe returns the setup and a working page for each preset. An owner may let a resource inherit the site's existing passcode gate or turn that inheritance off. The default 1,000,000-byte allowance is pooled across these new resources for each website. Resize phone photos before storing them as files.

Use storage_* tools for a selected team site and hack_event_storage_* tools for an organiser's custom event website. A public page uses SH.storage.kv(), SH.storage.sqlite(db).table(t) (list, get, add, edit, delete; pages never send SQL on a resource with a preset) or SH.storage.files() from https://simple-hack.app/auth.js; SH.mount(), SH.email and SH.requireSignIn() handle visitor sessions when a preset needs signed-in visitors. Team membership, event stage, deadline and organiser role checks remain server enforced. Joining, applications, team entries, judging and results are native event features on the trusted Simple Hack apex, separate from website storage.

Simple Hack organiser deletion: DELETE /v1/hack/events/{slug} with {"confirm":"<slug>"} works at any stage. Empty, unended events retain no-body deletion; otherwise 409 delete_only_empty explains confirmation. Settings requires typing the address name. Pages, results, team sites, entries, scores, votes, custom website, storage and access are removed permanently with no undo. Names stay reserved after anyone joins. The destructive hack_delete_event tool and run-hackathon always ask before deleting.
