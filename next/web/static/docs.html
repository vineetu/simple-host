API reference

Every route of the service. Paths under /v1/sites/{site} take an optional owner (a team handle). The default is you.

For AI readers there is also llms.txt.

Keys

Make a key in the dashboard. Send it as Authorization: Bearer <key>. A key acts as the person who made it. Revoke it in the dashboard and it stops at once.

Refusals

Every refusal is JSON, {"code": "...", "fix": "..."}, with an HTTP status. fix says in plain words what to do. When a limit was hit, the refusal names that limit.

Addresses

New accounts: https://<site>--<handle>.simple-host.site/. Existing accounts: https://<site>.<handle>.simple-host.app/. Use the address a route or tool returns, because old path-style links do not work.

The page helper

A page on a site loads one script. It runs in the visitor's browser.

<script src="https://simple-host.app/auth.js"></script>
CallWhat it does
SH.me()Who is signed in on this site, or nobody.
SH.signIn()Start sign-in with Google or an emailed code.
SH.signOut()Sign out of this site.
SH.requireSignIn()Sign in first if needed, then carry on.
SH.mount('#box')Show the sign-in box in that element.
SH.storage.sqlite(ns).table(t).add(row)Add a row.
.list(options)List rows.
.get(id)Read a row.
.edit(id, changes)Change a row.
.delete(id)Delete a row.
SH.storage.sqlite(ns).query(sql)Owner only. Read with SQL.
SH.storage.sqlite(ns).execute(sql)Owner only. Change with SQL.
SH.storage.kv(ns).keys()List value names.
SH.storage.kv(ns).get(key)Read a value.
SH.storage.kv(ns).set(key, value)Set a value.
SH.storage.kv(ns).delete(key)Delete a value.
SH.storage.files(ns).list()List files.
SH.storage.files(ns).get(path)Fetch a file.
SH.storage.files(ns).put(path, data)Save a file.
SH.storage.files(ns).upload(file)Upload a file from a file input.
SH.storage.files(ns).url(path)The address of a file.
SH.storage.files(ns).delete(path)Delete a file.
SH.storage.toObjects(result)Turn a SQL result into a list of objects.

What a page may do depends on the rules the owner set for that table, value set or file store: anyone, signed-in people, the row's author, or the owner. With no rules, only the owner can touch the data. Anonymous visitors can post only where the owner allows it and a spam check (Cloudflare Turnstile) passes.
